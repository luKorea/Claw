# Contract: Client Auto Update Flow

## Update Source

The app uses the Tauri updater static JSON endpoint:

```text
https://github.com/luKorea/Claw/releases/latest/download/latest.json
```

## Manifest Shape

```json
{
  "version": "0.1.4",
  "notes": "Release notes for this version.",
  "pub_date": "2026-06-12T00:00:00Z",
  "platforms": {
    "darwin-aarch64": {
      "signature": "base64-signature",
      "url": "https://github.com/luKorea/Claw/releases/download/v0.1.4/..."
    }
  }
}
```

The concrete platform keys and artifact URLs are generated by the Tauri release build. The application must not parse GitHub Releases directly.

## Frontend Wrapper Contract

### `checkForUpdate(options)`

Input:

```ts
{
  silent: boolean;
}
```

Output:

```ts
{
  status: 'available' | 'not-available' | 'error';
  update?: AvailableUpdate;
  message?: string;
}
```

### `downloadAndInstallUpdate(update, onProgress)`

Input:

```ts
AvailableUpdate
```

Progress callback:

```ts
{
  downloaded: number;
  contentLength: number | null;
  percent: number | null;
}
```

Output:

```ts
{
  status: 'ready-to-restart' | 'error';
  message?: string;
}
```

### `relaunchForUpdate()`

Requests an application relaunch after a successful update install.

## UX Contract

- Startup check failures are quiet.
- Manual check failures are visible in About settings.
- Download/install failures are visible in the update prompt.
- The user must explicitly click the update action before download/install starts.
